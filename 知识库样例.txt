AI Agent 设计原理知识库（示例文档，可直接上传百炼知识库）

一、核心公式
全书的核心公式是：Agent = LLM + 上下文 + 工具。其中 LLM 是大脑，负责理解意图、规划决策、判断下一步行动；上下文是眼睛，指 Agent 在每个决策点能看到的一切信息，包括环境状态、对话历史、用户记忆、领域知识和任务进展；工具是手脚，指 Agent 能执行的所有操作，包括搜索、代码执行、API 调用、文件操作等。
学术界对应关系为：LLM 对应策略 Policy，上下文对应观察空间 Observation Space，工具对应动作空间 Action Space。

二、Harness 工程
现代 Agent 的实际形态是 Agent = Model + Harness。Harness 指模型之外的一切工程能力，包括上下文管理、工具接口、约束护栏、输出校验和失败纠正五个方面。
上下文管理：确保模型在每个决策时刻拿到最相关、最少噪声的信息。
工具接口：标准化参数 schema 定义，管理调用的生命周期。
约束护栏：设定严格的行为和安全边界，对破坏性操作默认不信任。
输出校验：以程序化方式检查工具输出的正确性，例如对生成代码做静态检查。
失败纠正：自动处理局部失败，例如用修正后的参数重试，而不是中断整个流程。
Harness 工程才是竞争力的来源，因为大模型本身存在幻觉、参数错配、解析错误等不可预测性。

三、ReAct 循环
现代 Agent 的运行依赖 Thought → Action → Observation 的顺序循环。思考阶段规划下一步，行动阶段调用工具，观察阶段获取执行结果，循环累积的轨迹使模型能动态更新对环境的理解。

四、上下文工程
上下文决定 Agent 的能力上限。大模型 API 的 token 窗口被划分为静态前缀（系统提示词与工具 schema 定义）和动态轨迹（对话历史、工具调用、工具执行结果）两部分。
KV Cache 是模型内部机制，缓存历史 token 的 Key-Value 状态以避免重复计算。Prompt Cache 是推理引擎层优化，跨请求缓存相同的静态上下文前缀。命中 Prompt Cache 可将 token 成本降低约十倍，首 token 延迟从 3 到 5 秒降到约 0.5 秒。
追加式设计模式：为保持 Prompt Cache 命中，静态前缀必须绝对不可变，任何动态系统状态（时间戳、系统变量）都应作为新消息追加到轨迹末尾，而不是注入系统提示词。
上下文压缩：当历史过长时通过摘要或滑动窗口压缩，防止撑爆上下文窗口。

五、用户记忆与知识库
长期记忆指跨会话记住用户偏好与信息。RAG（检索增强生成，Retrieval-Augmented Generation）让 Agent 查询外部知识库，并以检索到的内容作为生成答案的依据，显著提升垂直领域准确率并减少幻觉。
知识库检索到的文本切片会占用模型上下文窗口，需要调整检索策略和文本长度。结构化索引与知识图谱是更高级的知识组织方式。

六、工具与 MCP
MCP（Model Context Protocol，模型上下文协议）是工具接入的标准协议。工具分三类：感知类（获取外部环境信息）、执行类（改变外部世界状态）、协作类（与其他 Agent 或人交互）。
工具设计原则：描述清晰以减少误调用，数量适宜以减少选择困难，支持异步调用以处理长耗时任务。主动工具发现指 Agent 在缺少工具时主动寻找可用工具。

七、Coding Agent
代码是"能创造新工具的工具"，代码生成被视为通用 Agent 的元能力。

八、Agent 评估
评估要把表现变成可比较的信号。包括评估环境设计、数据集设计、指标体系、统计显著性检验、可观测性，以及评估驱动的选型流程。

九、模型后训练
预训练、监督微调 SFT、强化学习 RL 三阶段。判断何时选 SFT、何时选 RL，并可将工具调用能力内化进模型权重。

十、Agent 的持续进化
从运行轨迹获得学习信号，更新知识、指令、程序与参数，使 Agent 在不改动权重的情况下持续成长，并实现从"工具使用者"到"工具创造者"的演化。

十一、多 Agent 协作
群体智能高于个体。涉及多 Agent 分类框架、何时超越单 Agent、共享上下文与隔离上下文的协作方式、常见失败模式，以及涌现的 Agent 社会。
